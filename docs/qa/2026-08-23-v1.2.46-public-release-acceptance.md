# Mirror X Codex v1.2.46 PUBLIC-FINAL-v16 验收报告

## Product Goal Understanding

- `Target users`：收到 ZIP 的陌生 Windows x64 用户，包括无 Codex、旧 Codex、已登录官方 Codex、仅持有 API Key、低磁盘和受企业策略管理的设备。
- `Core scenario`：解压 -> 校验 -> 安装 -> 本机预检 -> 验证 Key/模型 -> 选择 Pure 或 Mixed -> 建立基线并应用 -> 启动 -> 必要时恢复或卸载。
- `Primary user success outcome`：用户无需手改 `.codex`，模型可选、能创建聊天，原会话和插件保留，失败时能回到接入前状态。
- `Business goal`：形成不依赖制作机状态、可转发、可诊断、可恢复的 Windows x64 RC。
- `Non-goals`：不承诺 ARM64、32 位、裁剪系统、所有企业策略、第三方插件免登录，也不在包内分发任何 Key。
- `Quality risks`：Provider 表缺失、Pure/Mixed 串线、旧 Codex 缠绕 Sandbox RPC、企业策略禁止 Full access、低磁盘半写入、历史会话损失、WebView2/winget 缺失、未签名程序被拦截、旧 ZIP 混发。
- `Assumption`：收件人使用支持范围内的 Windows x64，拥有至少一个有效文本 Key，并能访问其 API 地址。

### Acceptance Decision

### Optimization Proposals

#### Immediate fix (before unrestricted public release)

1. 在一次性 Windows 11 x64 VM 和一台更新版 Windows 10 x64 上，用测试 Key 分别跑 Pure、Mixed、安装、升级、恢复和卸载。
2. 为三枚 EXE 和 setup 增加可信 Authenticode 签名。

#### Short-term improvement (next iteration)

1. CI 增加 Windows clean-runner 的静默安装、文件版本、启动烟测和卸载恢复。
2. Manager 增加“导出脱敏诊断包”，让外部用户能反馈问题而不误发 Key。

#### Structural optimization (root cause)

1. 发布流水线绑定 source fingerprint、Release EXE、setup payload 和最终 ZIP；任一源码或版本变化自动作废旧产物。
2. 建立固定兼容矩阵：Windows 11、Windows 10、无 WebView2、无 winget、低磁盘、企业策略、Store/Standalone Codex。
