## Product Goal Understanding

- Target users：不熟悉 `config.toml`、Provider、PowerShell 的普通 Windows 用户，以及需要 Pure API、Mixed API、Image Skill、历史会话和手机 Relay 的现有用户。
- Core scenario：安装后验证镜子AI Key，选择 Pure/Mixed 模式，可靠写入并启动 Codex；重复点击、升级、低磁盘、旧配置和异常退出时可解释、可恢复、不丢会话。
- Primary user success outcome：用户无需理解内部配置即可创建新会话、恢复历史会话、选择模型、调用工具和生图。
- Business goal：形成可公开分发、可升级、可回滚的唯一 Windows 交付版本。
- Non-goals：不整仓覆盖上游；不恢复复杂高级设置；不把 Image Skill 注册为 Codex Provider；不强杀 Codex/launcher。
- Quality risks：用户环境差异、旧配置残留、Provider 名称漂移、插件市场保留名、快速重复启动、端口释放延迟、低磁盘、大日志、损坏会话索引。
- Assumption：公开发布前仍有一台干净 Windows 设备用于安装、Pure/Mixed 真实 Key 与真实 Codex Desktop 的人工冒烟。

## Boundary and Destructive Cases

- 空 Key、空 Provider、重复模型、缺失 default model、非法 Codex path、损坏 JSON/TOML 均已覆盖。
- 快速重复启动、固定端口短占用、旧 launcher 清理等待均有有界行为；禁止无限等待和强杀未知进程。
- 会话索引使用 64MB 上限、预览 SHA-256、应用前二次快照校验、运行中拒绝、完整备份和原子替换。
- Marketplace 覆盖采用 staging/rollback；失败不会留下“配置新名、磁盘旧名”的半迁移状态。
- 破坏性案例只在测试临时目录运行，未对真实用户 HOME、`.codex`、服务器或安装目录执行。
