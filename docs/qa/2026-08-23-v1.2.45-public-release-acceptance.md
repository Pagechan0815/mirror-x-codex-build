# Mirror X Codex v1.2.45 PUBLIC-FINAL 验收报告

## Product Goal Understanding

- `Target users`：把安装包转发给其他 Windows 用户后，收件人可在没有制作机状态、没有内置 Key 的前提下完成 Codex 检测、Key 验证、Pure/Mixed API 接入、启动和恢复。
- `Core scenario`：安装 -> 检测或安装 Codex -> 填写至少一个文本 Key -> 真实验证并选择模型 -> 选择 Pure/Mixed -> 建立基线并应用 -> 启动 -> 必要时恢复。
- `Primary user success outcome`：不手改 `.codex`，不丢会话，不出现 `Model provider custom not found`，模型可选且可创建对话。
- `Business goal`：形成可公开转发、按用户安装、可恢复的 Windows x64 交付物。
- `Non-goals`：不承诺 ARM64、32 位、精简系统、所有企业策略或所有第三方插件免登录；不在安装包内分发任何 Key。
- `Quality risks`：Provider 表缺失、Pure/Mixed 串线、旧 Profile 覆盖实时配置、低磁盘半写入、会话归属不一致、无 Codex/winget/WebView2、未签名程序被拦截、旧 ZIP 被误发。
- `Assumption`：收件人使用受支持的 Windows x64，拥有至少一个有效文本 Key，并能访问其 API 地址。

### Acceptance Decision

当前产物不是“仅制作机器可用”的私有包：它不包含制作机路径、登录态、Key、服务器 SSH 凭据或会话，安装位置与配置均按收件人的 Windows 用户解析。功能逻辑和产物闭环达到可转发 RC 标准，但由于本机 Windows Sandbox 被禁用，无法把“全新 Windows 真实 Key 现场链路”伪装成已完成；因此结论保持 Conditional Accept。

### Optimization Proposals

#### Immediate fix (before unrestricted public release)

1. 在一次性 Windows 11 x64 VM 与一台更新版 Windows 10 x64 上，用测试 Key 分别跑 Pure、Mixed、安装、升级、恢复、卸载。
2. 为三枚 EXE 和 setup 增加可信 Authenticode 签名。

#### Short-term improvement (next iteration)

1. 在 CI 加入 Windows clean-runner 的安装器静默安装、文件版本、启动烟测和卸载恢复测试。
2. 在 Manager 增加“导出脱敏诊断包”，减少用户手工截取错误并避免误发 Key。

#### Structural optimization (root cause)

1. 发布流水线绑定 source fingerprint、Release EXE、installer payload 和最终 ZIP；任一源码变化自动作废旧产物。
2. 建立固定兼容矩阵：Windows 11、Windows 10、无 WebView2、无 winget、低磁盘、企业策略、Store/Standalone Codex。
