# Mirror X Codex v1.2.45 最终验收报告

结论：`Windows Release Candidate / Conditional Accept`。测试范围内无未关闭的 S0/S1 缺陷；自动化、静态验包与桌面/移动视觉回归通过。由于本轮明确不触碰当前 Codex、真实 `.codex`、生产服务器和真实客户 Key，真实 Key 全链路及全新 Windows 安装/卸载仍是发布前人工门禁。

## 1. Product Goal Understanding

- Target users：已有或准备安装 Codex Desktop、希望使用镜子AI Key，并需要保留官方登录、插件和历史会话的 Windows 用户。
- Core scenario：检测 Codex -> 登录镜子AI或手填 Key -> 真实验证模型 -> 选择混合/纯 API -> 建立还原点 -> 应用配置 -> 启动 Codex -> 可选手机续聊 -> 随时恢复。
- Primary user success outcome：无需理解 `config.toml`、`auth.json` 或本地数据库即可完成接入；失败时不覆盖未知状态，历史会话可见且可恢复。
- Business goal：形成具有镜子AI账号、分组 Key、Image Key、插件和移动控制能力的本机一体化接入工具。
- Non-goals：本轮不发布 macOS、新增计费系统、修改生产中转站，也不承诺任意远程会话的 provider 自动修复。
- Quality risks：Key/协议误判、混合与纯 API 串线、Codex 运行中写配置、低磁盘导致半写入、会话数据库与 rollout 不一致、插件缺失、安装中断、移动网络断开、provider 设置刷新失败后的恢复、窄屏操作困难。
- Assumption：最终人工验收使用一次性测试账号/Key 和可回滚的全新 Windows 虚拟机。

## 10. Regression Rules

- Smoke：Manager 加载、3/3 预检、Key 验证、模式切换、应用闸门、启动、恢复、移动连接。
- Critical business flow：账号/手填 Key -> 模型真实探测或复用 15 分钟同 Key 缓存 -> mixed/pure -> snapshot -> write -> 本地回读 -> launch -> restore。
- High-risk history：损坏配置、低磁盘、锁占用、安装中断、旧 provider 迁移、重复数据库、超大 rollout、Launcher 清理期重启。
- Cross-platform sanity：Windows desktop、320/390 手机竖屏、844 手机横屏、1440 desktop；macOS 仅编译/静态契约，不属于本次发布结论。
- 每次修改 `mirror_access`、`relay_switch`、`provider_sync`、`storage`、`watcher`、NSIS 或移动发送逻辑，必须重跑全工作区，不接受仅定向测试。
- 打包必须显式列出三枚正式 EXE；安装包和 ZIP 解包后逐文件与 Release SHA-256 比对。

- 当前用户保护：本次收尾没有停止、重启或修改正在使用的 Codex；没有读取/写入真实 `.codex`；没有连接生产服务器；没有运行安装包。

### Optimization Proposals

Immediate fix (before public release)：在一次性 Windows VM 用测试账号/Key 跑 NP-002~NP-010、AP-010、NU-004，并验证安装、升级、卸载、恢复；为 EXE/installer 增加可信代码签名。

Short-term improvement (next iteration)：增加受控 staging Key 的夜间真实流式 E2E；实现 provider 一致性核验和跨进程自动后修复队列；打包改为独立空 staging 目录并由 CI 断言文件数恒为 3；加入磁盘 95%/100%、断网、休眠唤醒的 GUI 自动化。

Structural optimization：为配置与会话恢复引入字段级三方合并和可视化冲突报告；在发布流水线实现 source-freeze hash，发现测试后源码变化立即作废构建；将 Windows Store、Standalone、低配设备和多数据库布局纳入固定兼容矩阵。
